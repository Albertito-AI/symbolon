# Implementation and test coverage

This map covers the [dated contract schema](../spec/2026-10-25.alpha1.contract.schema.json) and [current sandbox architecture](architecture.md). It describes package `0.1.0a1`, specification `2026-10-25.alpha1`, TEST units and the `exact-json-v1` acceptance rule. The initial source and test inspection used [899daae26f4f391317debf9fd83eeb70334665ed](https://github.com/Albertito-AI/symbolon/tree/899daae26f4f391317debf9fd83eeb70334665ed), before the documentation and CI increment. The direct contract-envelope tests were subsequently added against [940d331a166b58fcf03a1d59b16188be5e29dc19](https://github.com/Albertito-AI/symbolon/tree/940d331a166b58fcf03a1d59b16188be5e29dc19).

The rows group related requirements. They are a coverage map, not an exhaustive clause-by-clause conformance result. **Tested** means the named regression checks the stated local behaviour; **partial** identifies limits in direct test coverage; **fixture** identifies a synthetic demonstration or illustrative model; **planned** means the capability is absent. Passing checks do not establish legal, security or protocol certification. [Issue 9](https://github.com/Albertito-AI/symbolon/issues/9) remains open for uncovered clauses and continuing updates as roadmap work is implemented.

## Reproduction and versions

From the repository root, the existing source checks are:

```bash
PYTHONPATH=src python -m unittest discover -s tests -v
PYTHONPATH=src python -m symbolon demo --output artifacts/coverage-demo
PYTHONPATH=src python -m symbolon economics
```

Use a new demo output directory. A local replay on 14 November 2026 UTC (15 November Singapore time), using source `899daae26f4f391317debf9fd83eeb70334665ed` and Python 3.12.14, passed all 66 tests and reproduced the accepted `SETTLED` and disputed `RESOLVED` fixtures, with 10 journal entries, 20 postings and conserved TEST balances. An isolated local wheel build/install also reproduced those states and evidence digests from outside source. These are local observations, not a claim that a later hosted run passed.

The package declares Python `>=3.11`; CI exercises the narrower matrix `3.11`, `3.12`, `3.13`. Other versions/platforms are not established by that matrix. The installed-wheel step explicitly acquires the hash-pinned `setuptools==84.2.1` backend, then builds and installs the project without index access or dependency resolution. It uses separate build/runtime environments, clears source-path overrides, checks that imports come from runtime site-packages and preserves LICENSE/NOTICE in the wheel. The backend's [official instructions](https://setuptools.pypa.io/en/stable/userguide/quickstart.html) explain why a separate wheel package is unnecessary. The pin makes this acquisition explicit; it does not certify all bundled dependencies or guarantee bit-identical wheel archives. Generated wheels and demonstration data are temporary and are not published by this check.
